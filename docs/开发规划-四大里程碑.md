# 3kstory 业务目标与开发规划

## 一、业务目标与四大里程碑

| 里程碑 | 目标 | 核心产出 |
|--------|------|----------|
| **M1** | 实现 AI 生成视频 - 电影/电视解说 | 第三方视频平台账号接入（抖音、小红书、B站、微博），支持授权绑定与后续一键发布能力 |
| **M2** | 实现 AI 生成视频 - 短剧 | 短剧剧本→分镜→成片流水线，支持竖屏与发布到上述平台 |
| **M3** | 实现 AI 生成视频 - 电影 | 长片剧本、多镜头、多角色与更高时长/画质能力 |
| **M4** | 构建 AI 生成视频平台 | 多租户、计费、审核、数据看板与完整产品化 |

---

## 二、现状总结

### 2.1 已有能力

- **后端**：Go + Gin，PostgreSQL + Redis，JWT 认证，GORM 模型（User、Project、Scene、AITask）。
- **前端**：Next.js 14 + React 18 + TypeScript，Tailwind + Ant Design，Zustand 登录态，Axios 封装。
- **AI**：剧本生成（通义 / vLLM / Ollama 可切换），Runway / Pika / 本地 ffmpeg 三种视频生成方式，配图与审核为占位。
- **视频**：`generate-video`、`video-status`、`videos` 列表、取消接口已有，但 **视频任务持久化未实现**（SaveVideoTask/GetVideoTask/List 为占位）。

### 2.2 与 M1 相关的缺口

- **平台账号**：代码中 **无** 抖音、小红书、B站、微博 的 SDK 或开放平台 API 调用；仅文档中有竞品/规划描述。
- **OAuth**：无统一 OAuth 配置、回调路由、Token 存储与刷新逻辑。
- **数据模型**：无「用户-平台-授权信息」表，无法做「已绑定账号列表」与「发布时选号」。

因此 **第一个里程碑需要从零设计并实现「第三方视频平台账号接入」**，为后续「一键发布到抖音/小红书/B站/微博」打基础。

## 三、详细开发规划

### 3.1 里程碑一：第三方视频平台账号接入（当前重点）

**目标**：用户可在 3kstory 内绑定抖音、小红书、B站、微博账号，并可在后续里程碑中基于绑定关系进行发布。

**子任务**：

1. **数据与配置**
   - 新增 `platform_accounts` 表：user_id、platform（douyin/xiaohongshu/bilibili/weibo）、open_id、union_id、access_token、refresh_token、expires_at、平台昵称/头像等。
   - 配置层：各平台 AppID/AppKey、AppSecret、授权 Scope、RedirectURI、AuthorizeURL、TokenURL（可从 env 读取，便于多环境）。

2. **后端 OAuth 流程**
   - 提供「获取授权链接」接口：前端请求后重定向用户到对应平台授权页。
   - 各平台 OAuth 回调统一到后端（如 `/api/v1/platforms/:platform/callback`），用 code 换 token，落库，再重定向到前端「绑定成功/失败」页。
   - 接口：列出当前用户已绑定平台、解绑某平台、可选「刷新 token」定时任务或按需刷新。

3. **前端**
   - 「账号绑定」入口（如设置页或独立「平台账号」页）：展示抖音/小红书/B站/微博 的绑定状态，未绑定显示「绑定」按钮，已绑定显示昵称+「解绑」。
   - 点击「绑定」跳转后端返回的授权 URL；回调后由后端重定向回前端并展示成功/失败 toasts。

4. **安全与合规**
   - access_token/refresh_token 仅存后端，不向前端下发。
   - 回调校验 state 防 CSRF；redirect_uri 与各平台后台配置一致。

**验收标准**：用户能完成至少一个平台（建议先做 B站 或 微博，文档与调试相对简单）的授权绑定与解绑，并在「已绑定列表」中正确展示。

---

### 3.2 里程碑二：AI 生成视频 - 短剧

- 在现有剧本生成与 Runway/Pika/本地视频 能力上，固化「短剧」流程：剧本 → 分镜 → 按镜生成视频 → 合成竖屏成片。
- 与 M1 衔接：成片后可选择已绑定的抖音/小红书等账号进行发布（调用各平台「发布视频」开放接口）。
- 可选：引入 OpenClaw/ClawVid 作为补充管线（见下文 OpenClaw 小节）。

### 3.3 里程碑三：AI 生成视频 - 电影

- 长剧本、多镜头、多角色、更长时长与画质策略；可能涉及分段生成、剪辑与审核流程。
- 发布仍复用 M1 的平台绑定与 M2 的发布能力（部分平台支持长视频）。

### 3.4 里程碑四：AI 生成视频平台

- 多租户与权限、计费（积分/套餐）、内容审核（含敏感词与画面）、数据看板与运营配置。
- 将现有单机/单库能力扩展为可配置、可运营的平台产品。

## 四、OpenClaw 的结合方式与必要性

### 4.1 OpenClaw 是什么

- **OpenClaw** 本身是「会做事的 AI」智能体（个人助手），支持自然语言任务与多端（如 WhatsApp、Telegram 等），**不是** 专门的视频生成平台。
- 生态中有与视频相关的开源项目：
  - **openclaw-video**：文本→视频管线（TTS、Remotion 渲染、风格化等）。
  - **ClawVid**：短视频生成 CLI（YouTube Shorts / TikTok / Reels），TTS、Kling 2.6、多比例字幕等。

### 4.2 是否必须用 OpenClaw

- **非必须**。当前 3kstory 已有 Runway/Pika/本地 ffmpeg 与剧本生成，**不依赖** OpenClaw 即可完成 M1～M3 的视频生成与发布。
- 若希望 **增强自动化与编排能力**，可把 OpenClaw 作为「可选组件」使用。

### 4.3 如何结合使用（建议）

1. **任务编排与发布自动化（推荐）**
   - 将 OpenClaw 作为「发布/运营助手」：用户用自然语言说「把刚才的短剧发到抖音」，由 OpenClaw 解析意图，调用 3kstory 后端「选择项目 + 选择绑定账号 + 调用发布接口」的 API，完成一键发布。
   - 实现方式：3kstory 提供 REST API（发布、列表绑定账号等），OpenClaw 通过 Function Calling 或内置插件调用这些 API。

2. **视频管线补充（可选）**
   - 若希望引入「TTS + 字幕 + 固定模板」的快速成片，可参考 **openclaw-video** 或 **ClawVid** 的流程，在 3kstory 中增加一条「模板化短视频」管线，与现有 Runway/Pika 管线并列，由用户在创建项目时选择「AI 自由生成」或「模板化短视频」。

3. **落地顺序建议**
   - **M1**：不依赖 OpenClaw，先完成平台账号接入与基础 API。
   - **M2**：短剧生成与发布流程跑通后，再考虑接入 OpenClaw 做「自然语言发布」或引入 ClawVid 式管线作为可选能力。
