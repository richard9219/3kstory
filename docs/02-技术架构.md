# 3kstory 技术架构

## 当前主线架构

短期内不再以 AWS 为主线，当前推荐架构调整为「本地 Mac 主机 + Windows 外星人辅助节点」。

```text
┌──────────────────────────────────────────────────────────────┐
│                    Mac 主开发机 / 运营机                    │
├──────────────────────────────────────────────────────────────┤
│ Frontend (Next.js)                                          │
│ Backend API (Go + Gin)                                      │
│ local-video-service (ffmpeg)                                │
│ PostgreSQL                                                  │
│ Redis                                                       │
│ 本地文件目录：.local/videos / .local/tts                    │
└──────────────────────────────────────────────────────────────┘
                              │
                              │ 局域网 / Tailscale
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                    Windows 外星人辅助节点                    │
├──────────────────────────────────────────────────────────────┤
│ Ollama / vLLM                                               │
│ 后续可扩展：图像生成 / ASR / 多模态审核 / 批处理 worker      │
└──────────────────────────────────────────────────────────────┘
```

## 当前服务职责

### Mac 主机

- 前端页面与运营操作入口
- 后端 API、鉴权、项目管理、任务记录
- PostgreSQL 与 Redis
- 视频合成服务
- 电影解说流程编排：
  - 生成解说文案
  - 调用本地 TTS
  - 截取原视频素材
  - 叠字幕并合成成片

### Windows 外星人

- 为 Mac 后端提供本地 LLM 推理能力
- 作为图像/视频等重计算能力的预留节点
- 后续如有需要可接入离线 worker 和批处理流程

## 当前实现路线

### Phase A：本地闭环验证（当前）

- Mac 单机跑通前后端、数据库、Redis、视频服务
- Windows 跑通 Ollama 或 vLLM
- 先产出几期电影解说视频并手动发布

### Phase B：增强本地智能能力

- 引入更稳定的脚本生成与结构化输出
- 增加音频、字幕、素材切片的质量控制
- 增加本地素材预处理、ASR、镜头切分

### Phase C：再评估线上化

- 当选题、产能、发布流程验证稳定后
- 再考虑对象存储、自动发布、远程访问和云上部署

## 2026-03 导演工作台架构增量

新增了一条“镜头级编排 -> 导演版合成 -> 门禁发布”的执行链路：

```text
StoryboardShot(可执行时间轴字段)
  ├─ track_index / timeline_start_ms / timeline_duration_ms
  ├─ transition_type / transition_duration_ms
  └─ clip_status / clip_video_url / clip_score

镜头执行层
  ├─ /storyboard-shots/:shotID/generate
  └─ /storyboard-shots/:shotID/regenerate

导演合成层
  └─ /storyboard-timeline/render
     - ffmpeg xfade + acrossfade
     - 输出 director_cut VideoTask

发布门禁层
  ├─ /storyboard-timeline/exports/:exportID/auto-publish
  └─ /storyboard-timeline/exports/:exportID/publish
     - 复用 PUBLISH_QUALITY_THRESHOLD
     - 校验平台账号是否已绑定
```

### 关键设计点

- 时间轴是执行源，不再只是分镜台账。
- 转场按镜头 `transition_type` 渲染，默认 `cut`，支持 `fade/wipe/match`。
- 导演版导出任务记录 `quality_score` 与 `quality_gate_passed`，供发布流程直接复用。
- 平台发布前必须先通过质量门禁，并且用户已绑定对应平台账号。

## 现阶段原则

- 先解决内容生产效率，再解决线上部署
- 能在本地闭环的能力尽量不要提前上云
- 外星人节点只承担重计算，不承担对外主站入口
