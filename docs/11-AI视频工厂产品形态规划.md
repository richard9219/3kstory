# 11 AI视频工厂产品形态规划

本文档用于统一三千影视的产品定位、阶段路线、官网信息架构、管理系统模块和 AI 视频生成接入方向。

## 1. 产品定位

三千影视不是单点的影视解说工具，也不是单一短剧生成器，而是一个面向多内容形态的一体化 AI 视频工厂。

统一定位：

- 面向影视解说、AI短剧、AI电影、广告与品牌内容的生产系统
- 以项目、资产、脚本、镜头、成片和分发为核心对象
- 以模型编排、任务调度、质量控制和渠道投放为核心能力

对外表达建议：

- 一句话：三千影视是一个从脚本到成片再到分发的 AI 视频工厂
- 官网标题：AI 视频工厂，而不是 AI 短剧平台
- 管理后台名称：工厂控制台，而不是单纯运营看板

## 2. 业务阶段

### 阶段一：影视解说工厂

目标：

- 跑通高频、可规模化的生产线
- 建立选题、脚本、旁白、素材、成片、发布的闭环

核心能力：

- 输入影片标题、剧情简介、创作要求，生成解说稿
- 连接 TTS、字幕、素材装配、视频生成服务
- 绑定抖音、小红书、B站、微博渠道
- 跟踪任务状态、产量、完成率和复用率

核心指标：

- 单条视频平均生成时长
- 单条视频平均成本
- 发布成功率
- 单项目复用率

### 阶段二：AI短剧工厂

目标：

- 从单条解说视频升级到连续内容生产
- 建立人物、场景、道具、分镜、镜头版本体系

核心能力：

- 项目级世界观、角色和资产库管理
- 章节工作台和分镜编辑器
- 分镜中心升级为可执行时间轴（镜头轨道、起始时间、转场、锁定）
- 镜头卡支持拖拽改轨道与时间位置，替代纯表单输入
- 镜头参数控制：景别、运镜、时长、口型、表情、配乐
- 多模型混合生产：文生图、图生视频、角色一致性控制

核心指标：

- 单集产能
- 镜头返工率
- 角色一致性评分
- 爆款内容复用率

### 阶段三：AI电影工厂

目标：

- 承接长片内容规划与高一致性镜头生产
- 支撑章节、幕结构、长周期制作和版本迭代

核心能力：

- 长片项目树管理
- 章节级分镜和资产继承
- 角色弧线、关键场景、节奏控制
- 多轮审片、版本对比和批注系统

核心指标：

- 长片章节交付速度
- 长镜头一致性
- 资产复用比例
- 版本审校效率

### 阶段四：广告与品牌内容工厂

目标：

- 复用前面三阶段积累的资产和流程
- 承接商业内容订单和品牌内容自动化生产

核心能力：

- 品牌模板、视觉规范、脚本模板管理
- 商品卖点拆解和广告镜头模板
- 多平台规格适配：横版、竖版、短版、信息流版

## 3. 官网信息架构

首页建议结构：

1. 顶部主张：AI 视频工厂
2. 四条生产线：影视解说、AI短剧、AI电影、广告内容
3. 工厂能力：脚本、分镜、资产、视频生成、分发
4. 控制塔能力：任务、模型、成本、质量、渠道
5. 典型流程：需求输入 -> 模型编排 -> 生成 -> 审核 -> 发布
6. 平台接入：抖音、小红书、B站、微博

官网文案原则：

- 不再把自己限定为短剧平台
- 不再强调本地 ffmpeg 方案
- 突出模型能力、生产线能力和渠道能力

## 4. 管理系统模块

建议把后台拆成 6 个模块：

### 4.1 工厂总览

- 任务总量
- 完成率
- 渠道状态
- 产能趋势
- 成本趋势

### 4.2 项目中心

- 影视解说项目
- 短剧项目
- 电影项目
- 品牌项目

### 4.3 资产中心

- 角色库
- 场景库
- 道具库
- 品牌模板库
- 提示词模板库

### 4.4 生产中心

- 脚本生成
- 分镜生成
- 可执行时间轴编排
- 旁白生成
- 视频生成
- 后期合成（支持按转场类型渲染导演版）

### 4.5 模型中心

- 文生文模型
- 文生图模型
- 图生视频模型
- TTS 模型
- 审校模型

### 4.6 分发与复盘

- 平台绑定
- 发布排期
- 发布记录
- 数据回收
- 素材复用建议

## 5. AI 视频生成接入原则

核心原则：

- 本地 ffmpeg 仅作为调试兜底，不应再作为主生产路径
- 默认应优先走云端 AI 视频生成服务
- 支持主引擎 + 备选引擎 + 本地兜底三层策略

补充：导演版导出可使用本地 ffmpeg 进行快速合成，作为运营复审与发布前版本，不与云端镜头生成策略冲突。

## 7. 发布前门禁与渠道发布闭环

新增发布闭环建议：

1. 导演版导出后自动计算 `quality_score`。
2. 使用统一阈值 `PUBLISH_QUALITY_THRESHOLD` 做门禁。
3. 门禁通过后才允许进入平台发布动作。
4. 发布前校验用户平台账号是否已绑定。
5. 记录导出版本在各平台的发布时间与状态，支持复盘与复用推荐。

建议的接入顺序：

1. Runway 作为主视频生成引擎
2. Pika 作为备选视频生成引擎
3. 本地调试链路只用于开发和回归验证

后端需要具备的能力：

- 根据配置自动选择优先 provider
- 失败自动降级到备选 provider
- 保留任务追踪、状态轮询、错误记录和回放能力
- 后续扩展更多视频模型时，不改变上层业务接口

## 6. 当前建议

当前仓库应优先完成的事情：

1. 统一对外文案为 AI 视频工厂
2. 管理后台从运营看板升级为工厂控制台表达
3. 默认走云端视频模型，而不是本地渲染链路
4. 为短剧和电影阶段预留资产中心、分镜中心和模型中心入口

这意味着当前阶段的产品目标不是“做一个本地工具”，而是“先搭一条能扩到多内容形态的云端生产线”。
